# Prompt Forge

**为长对话设计的提示词生成器。**

不是模板拼接。你把需求说清楚，它调用大模型现场写出一段针对这个任务的提示词——包含角色定义、能力边界、输出规范，以及防止多轮对话跑偏的锚定语句。

> 在线演示：https://lbwapi.online/tools/prompt-forge.html

---

## 为什么需要它

大多数"提示词生成器"做的事情是把几个选项拼成固定句式：

```
你是一个【专业】的【写作】助手，请【认真】回答我的问题。
```

这类提示词有三个致命问题：

1. **不可验证** —— 模型无法判断自己有没有做到「专业」「认真」，只能退回最省力的通用模板
2. **没有边界** —— 没写不做什么，模型遇到边界情况就自由发挥或直接拒绝
3. **撑不住长对话** —— 聊到第 20 轮，最初那句设定在注意力里的权重已经被稀释掉了

Prompt Forge 的做法是**针对你这一个任务现写**，而不是套模板。

## 五种模式

| 模式 | 用途 | 典型场景 |
|---|---|---|
| **角色锚定** | 为长期使用的助手设定身份与规则 | 每天都要开的工作会话 |
| **长对话压缩** | 把历史提炼成状态快照，替换旧上下文 | 对话过长、上下文快满 |
| **跑偏纠回** | 生成注入指令，把跑丢的角色拉回来 | 模型开始拒绝、跑题、格式乱掉 |
| **场景定制** | 针对具体任务生成带步骤的提示词 | 一次性任务、复杂交付 |
| **问题诊断** | 指出你现有提示词的问题并改写 | 写好了但效果不好 |

## 核心设计：长对话压缩

这是和其他工具拉开差距的地方。

**问题**：模型没有真正的记忆。每轮对话都是把全部历史重新读一遍。历史越长，最初的角色设定权重越低。

**常见错误解法**：再强调一遍。效果甚微，而且越强调越像在吵架。

**正确解法**：在上下文快满时，用一段信息密度极高的**状态快照**替换掉原始历史。快照必须包含五项：

```
1. 任务目标      —— 最终要交付什么
2. 已定事实      —— 已确认的决策与结论（只记结论，不记过程）
3. 已排除方案    —— 明确写「不要再提」
4. 当前进度      —— 完成到哪，下一步是什么
5. 待确认问题    —— 还没定的事
```

生成的快照开头会强制声明「本快照为唯一有效上下文，与此前任何对话记忆冲突之处一律以本快照为准」——这句是整个机制的锚点。

## 不绑定模型

生成的提示词里：

- ❌ 不出现 `你是 GPT-4` / `你是 Claude` 这类模型名
- ❌ 不使用任何厂商特化语法（XML 标签、特殊分隔符等）
- ✅ 只用通用自然语言描述，可直接贴进任何客户端

## 快速开始

### 1. 纯前端使用（不需要后端）

直接用浏览器打开 `web/index.html` 会看到界面，但没有后端就无法生成。

### 2. 完整部署（需要 PHP + 一个 OpenAI 兼容接口）

```bash
# 1) 放到你的 Web 目录
cp -r web/    /var/www/html/prompt-forge/
cp -r server/ /var/www/html/prompt-forge/api/

# 2) 配置 API
cp server/config.sample.php server/config.php
vim server/config.php        # 填入你的 api_base / api_key / model

# 3) 确认目录可写（限流计数存在这里）
mkdir -p server/.store && chmod 755 server/.store
```

前端默认请求 `/api/prompt.php`。如果你的路径不同，改 `web/index.html` 里的这行：

```js
fetch('/api/prompt.php', { ... })
```

### 3. 配置项

```php
return [
    'prompt_forge_api_base' => 'https://api.openai.com/v1',  // 任意 OpenAI 兼容接口
    'prompt_forge_api_key'  => 'sk-...',
    'prompt_forge_model'    => 'gpt-4o-mini',                // 建议用小模型，快且便宜
    'prompt_forge_rpm'      => 6,                            // 每 IP 每分钟次数
    'prompt_forge_daily'    => 60,                           // 每 IP 每天次数
    'prompt_forge_max_in'   => 4000,                         // 输入字符上限
    'prompt_forge_timeout'  => 90,
];
```

**模型选择建议**：这个工具的 prompt 本身不复杂，用便宜的小模型就够。实测 `deepseek-v4-flash` 生成 1500 字约 15 秒，效果好于多数大模型——因为它生成的是结构化指令，不是创意写作。

## 接口

```
POST /api/prompt.php
Content-Type: application/json

{
  "mode":    "anchor|compress|resume|scenario|diagnose",
  "input":   "你的需求描述",
  "context": "可选，已有对话或你现有提示词",
  "tone":    "precise|strict|friendly",
  "lang":    "zh"
}
```

响应：

```json
{
  "ok": true,
  "mode": "anchor",
  "prompt": "生成的提示词正文",
  "chars": 1517,
  "usage": { "prompt_tokens": 420, "completion_tokens": 980, "total_tokens": 1400 }
}
```

失败：

```json
{ "ok": false, "error": "请求太频繁，请稍后再试" }
```

## 内置防护

- **IP 限流**：每分钟 / 每天双层计数，存在 `server/.store/pf_rate.json`
- **输入长度限制**：默认 4000 字符，防止刷 token
- **上下文截断**：超过 12000 字符自动截断
- **API key 不下发**：所有调用在服务端完成，前端只拿到生成结果

## 已知限制

- 每次生成消耗上游 token，高频使用需要加缓存
- 生成质量依赖上游模型能力，小模型偶尔会漏掉「锚定语句」
- 没有多语言界面（输出语言由 `lang` 参数控制，但 UI 是中文）

## 效果示例

输入：
> 我要一个帮我审代码的助手，只做 review 不改代码，输出分必须改和建议改两档

输出（节选）：

```markdown
# 角色
你是代码审查助手。服务对象是提交代码的开发者。
职责：阅读给定代码，指出缺陷与风险，给出修改方向。
你不修改代码，不重写文件，不生成补丁。

# 能力边界
**能做**
- 静态阅读：正确性、边界条件、错误处理、空值与越界、并发安全
- 模式识别：重复代码、过深嵌套、命名与职责不匹配

**不做**
- 不输出完整重写文件；需要示范时最多给 3-5 行 diff 片段
- 不评价代码风格偏好（缩进、引号）除非违反项目既有约定

**超出范围时**
第一句写「这超出审查范围：<原因>」，第二句给出可行替代。

# 输出规范
分两档：
- **必须改**：会导致错误、安全问题、数据损坏
- **建议改**：可维护性、性能、可读性

每条格式：`行号 | 问题 | 原因 | 修改方向`
```
